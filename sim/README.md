# sim —— 机械臂二维仿真（侧视）

单文件前端，纯静态，没有后端。**双击 `sim/index.html` 就能用**（`file://` 下 `arm_core.js`
是普通 `<script>`，不需要起服务器）。

```
sim/
├── index.html          画布 + 参数面板 + 预设 + 物块 + 导入导出（全部 UI）
├── arm_core.js         平面 2R 正逆解，逐行对应 Algorithm/src/arm_kinematics.cpp
├── stick_limit.js      摇杆软件限位：末端域（固件现状）vs 关节域贴边滑（§8）
├── cube3d.js           20 mm 立方体的位姿与正交投影（6 面编号、画家排序、明暗）
└── verify/
    ├── probe.cpp       把真实的 arm_kinematics.cpp 编成对拍探针
    ├── compare.js      18881 个点上对比 arm_core.js 与固件实现
    ├── stick_test.js   摇杆限位的 6 条断言（不冲、不抖、贴边滑、不撞车）
    ├── stick_probe.cpp 把真实的 arm_limit.cpp 编成对拍探针（固件几何）
    └── stick_port_test.js  固件贴边滑的 6 条断言 + 与 JS 逐帧对拍
```

## 1. 坐标与几何（原点 = 臂底座中心）

`+x` 指车头前方，`+y` 指上，单位 mm。底盘画在原点周围，按下面的实测值摆：

| 量 | 值 | 来源 / 含义 |
| --- | --- | --- |
| 底盘长度 `L` | **265.08** | 259.08 + 6 |
| 底座中心 → 底盘前端 | **72.46** | ⇒ 后端在 x = −192.62 |
| 底盘下沿离地 | **37** | 车轮半径取它，轮轴在底盘下沿 |
| 底盘本体厚度 | **40** | 上表面 = y = 0 = 臂底座 |
| 臂底座离地 | **77** | 37 + 40（地面画在 y = −77） |
| 大臂 `L1` | **76.00** | 肩轴 → 肘轴 |
| 小臂（腕点）`L2` | **40.08** | 固件现值，只到腕点 |
| 工具延伸 | **128.35** | 夹爪末端到小臂外侧轴心 |
| **真实小臂 `L2Σ`** | **168.43** | 40.08 + 128.35（逆解用的是它） |
| **夹爪占末端** | **46.00** | 最后 46 mm 是夹爪本体，夹取点可在其中取（§2） |
| 指尖最大伸展 | **244.43** | L1 + L2Σ |

关节与固件同一套 `kGeom`：θ1 ∈ [0°,180°] zero 90°，θ2 ∈ [−45°,+135°] zero 45°，
`deg_per_percent = 0.9`，`elbow_sign = +1`（高肘：θ2 的符号与目标 x 的符号相反）。

## 2. 夹爪不是点，是最后 46 mm 的一段线

末端 46 mm 全是夹爪，**夹取点可以落在这一段上任意位置**（`s` = 距指尖多远）。
所以逆解用的不是固定小臂长，而是 `L2Σ − s`：

- 画布里绿点 = 当前夹取点，橙色 = 夹爪，青色 = 小臂（到夹爪根）；
- 点画布时先按当前 `s` 解，解不中就沿整条夹爪线扫一遍，取离当前 `s` 最近的精确解
  （点哪就咬哪，`s` 自动跳到能咬住的位置）；
- 右侧「夹取点」滑块可以手动沿夹爪线拖：姿态不变、夹取点跟着滑；
- 读数里「夹取范围」给出这个目标点能被夹爪的哪些 `s` 咬住（例如 `s 22 ~ 32 mm`）。

画布上那块夹取范围就是这 46 mm 扫掠出来的，不是单点可达域。三块颜色：

| 颜色 | 含义 |
| --- | --- |
| 青 | **固件能夹住**：存在某个 `s`，`solve_xy` 既不径向钳位也不裁角，选支规则（x 与 θ2 反号）也通过 |
| 琥珀 | **只有另一支能到**：把臂折过来够得到，但 θ2 符号与固件选支相反，固件解不出、不会下发 |

**干涉即不可达**：大臂 / 小臂 / 夹爪任一段碰进底盘（上表面留 1 mm 间隙，底座那 14 mm 不算）
或钻到地面以下，这个位置就直接算「碰不到」——掩码**不画**、点它**不摆臂**（读数写
「机械干涉（小臂 + 夹爪 撞底盘）→ 碰不到」）、预设标「干涉」。顶部那条
`撞底盘/地面已排除 ≈ X mm²` 就是被排除掉的那块面积。

**换真实小臂之后长什么样**（页面顶部「派生」框实时算同一组数）：

```
指尖 r_max = 244.43
指尖 r_min 右（θ2=−45°）= 228.58    左（θ2=+135°）= 126.66
夹取点 s=23 时最大伸展 = 221.43
地面 y=−77 上：固件能夹 x = 168.0 ~ 225.0（底盘前端外 95.5 ~ 152.5 mm）
```

也就是说：**原来那 8 条 `kPoses`（r≈110）全部落在内半径以内**，会被沿方位钳到 228.6 的外圈上
——页面里点「载入固件现值」看到 8 条全是「钳位」就是这个原因，不是仿真算错，是固件的
`fore_mm` 还是 40.08。

另外画布上 **x = 0 有一条竖直的断崖**：右边只能用 θ2<0（内半径 228.58），左边能用 θ2>0
（内半径 126.66），所以 y 在 126~228 之间时「只有左半边能到、右半边到不了」。
这是「高肘选支 + 不对称行程」的直接后果（`debugv0.2.md` 的 D-3 / R-2），不是画错。

还有 **正前方 168 mm 以内够不到**：L1 只有 76、小臂 168，肘部前侧又只放开 45°，夹爪收不到脚边。
要改只能动 `elbow.min_deg` 或连杆长度。

## 4. 物块：20 mm 立方体 + 重量

目标物是 **20×20×20 mm、10 g** 的立方体（边长/质量都能改）。三个层面都在页面里：

**① 夹取交互**
- 「夹取物块」：物块离夹取点 ≤ 14 mm 时咬住，同时把 `S3` 打到 −100%（夹紧）；
- 咬住后物块中心 = 夹取点，跟着臂走；姿态 = 前臂方向（yaw）+ 腕 `S4` 的 roll；
- 「松开 / 掉落」或把 `S3` 拖到 ≥ 0（张开）→ 物块按 **½gt²** 自由下落，落到地面或底盘上表面停住
  （下落用时间解析式，后台标签页被节流也不会变慢动作）；
- **落地是实体接触**：按最低那个**顶点**结算高度，斜着的方块不会插进平面；
  落地后 180 ms 内**自动翻身躺平**（就近选一个面朝下），读数里 `躺平 / 斜着` 和 `压入 x mm`
  就是这件事；夹着往平面里压同样会标红（`压进平面`）；
- 「物块回地面」把它放回 x = 200 的地面。

**② 静力学**（每帧算）
```
肩力矩 = g·Σ mᵢ·xᵢ ，肘力矩 = g·Σ mᵢ·dᵢ·cosψ   （含两段臂的质量，咬住时再加物块）
载荷率 = |τ| / 额定（SG90 1.8 kg·cm = 0.176 N·m），>100% 标红
夹持：需要 F ≥ m·g / (2μ)；可用 = 最大夹紧力 × |S3|/100，不够就标「会打滑」
```
默认参数下，臂摆平举着这个 10 g 物块时肩关节已经到 **69~85% 额定** —— 这就是这条短大臂的真实余量。

**③ 六面显示 + 3D 位姿小窗**
- 主视图里物块画成真实轮廓（8 顶点投影的凸包，随 yaw/roll 转）；
- 左下角小窗是正交投影的 3D 立方体：**6 个面各一个颜色 + 编号**（1 +u / 2 −u / 3 +v / 4 −v / 5 +w / 6 −w），
  背面剔除 + 画家排序 + 简单明暗，三条彩线是 u（前臂）/ v（夹爪开合）/ w（侧向）轴；
- 拖着 `S4` 或改 yaw，就能看到哪个面朝向夹爪 —— 换面抓取的时候看这个。

> 还没做的两件事（后期）：车上储存区的设定、底盘斜坡做反面。现在**前后都算工作区**，
> 拟合出来的 `kWorkspace` 会跨肩轴（x_min < 0），此时自检里那条 `x_min > 0` 会变成黄色提示：
> 固件 `arm_config.hpp` 的 `static_assert` 得一起放开，否则编不过。

## 5. 与固件的一致性（已对拍）

`arm_core.js` 不是另写一套，是 `solve_xy` / `solve_forward` 的逐行移植（同样的圆环钳位顺序、
同样的高肘选支、同样的 `d1` 归一化到 (−180,180]、同样的 1e-3° 限位容差、同样的 FK 回算）。
夹爪只是在外层把小臂长度换成 `L2Σ − s`，公式一字未改。

在仓库根目录跑（两行，照抄）：

```bash
g++ -std=c++14 -O2 -I Algorithm/inc Algorithm/src/arm_kinematics.cpp sim/verify/probe.cpp -o sim/verify/probe.exe
node sim/verify/compare.js
```

上次结果（L1=76 / L2Σ=168.43）：

```
对拍点数：逆解 18881（奇异带 9276），正解 6561
  IK 位置最大偏差  1.43e-4 mm
  IK 角度最大偏差  4.51e-4 °
  IK 行程最大偏差  4.97e-4 %
  IK 标记不一致    0 / 9605        ← reachable / limited 与 C++ 完全同判
  奇异带（r≈内/外弧、顶限位）位置 0.3641 mm / 角度 0.1224 °（float32 vs double）
  FK 位置最大偏差  7.86e-5 mm
PASS
```

那 9276 个「奇异带」点是目标正好贴在外弧/本侧内弧、或解出来正好顶在限位上：此时
`cos_elbow → ±1`，`θ = acos(·)` 的敏感度按 `sqrt(eps)` 放大，float32 的 1e-7 舍入就能让角度差
0.02°、位置差 0.36 mm。**0.36 mm 已经是一个舵机步进（0.9° ≈ 2.6 mm 末端）的 1/7**，可以忽略；
这也是开环系统本来的分辨率。

画布上的夹取范围是**扫掠出来的掩码**（每个 (θ1,θ2) 画一条 46 mm 夹爪线，1°/0.5° 步长，
栅格 2 px ≈ 1.2 mm，再做一次针孔填充）。抽 600 个随机点与逐点逆解对比：漏画 0 个，
边界上 3 个点相差 ≤1 格。

## 7. 已知限制

- **128.35 的两种读法**：本页按「腕点小臂 40.08 + 工具 128.35 = 168.43」建模型（按 1.py 的
  「现有小臂长加上这个距离」）。如果 128.35 其实是从肘轴量起（真实小臂就是 128.35），
  把「工具延伸」改成 **88.27**（= 128.35 − 40.08），其它不动。
- **46 mm 当夹爪长度用，不是开口宽度**：夹取点沿夹爪中线取。若 46 其实是开口宽度，
  把「夹爪占末端」改成 0（夹取点回到指尖），开口另算。
- **碰撞只查线段**：大臂/小臂/夹爪当直线段处理（分别采样 6/8/4 点），不认舵机本体、线束、支架；
  底座 14 mm 内不算干涉（那圈本来就坐在底盘上）。
- **腕 `S4` 不参与解算**：二维模型假定它是沿小臂的 roll；若实物是 pitch，2R 模型失效，
  得升 3R（和 `debugv0.2.md` 的 D-5 同一条）。
- **参数存本地**：改过的参数存在 `localStorage`，换机器/清缓存就回到默认；要长期保存请导出 JSON。
- **物块只是刚性方块**：不建模转动惯量、碰撞反弹、夹爪指面材料；力矩按静力学算，不含加减速。

## 8. 摇杆 · 软件限位（`stick_limit.js`）

右栏第一块。拖圆盘 = 推左摇杆，`X` 前伸 / `Y` 抬升，保号平方律，死区可调；
时间步长由 rAF 给，上限 = `kMotion.maxElapsedMs`（和固件一样能挡住卡顿）。
摆好后点「暂停积分」，臂就停在那儿；要看稳态行为就勾「松手保持推杆」。

### 8.1 两套策略，只差「走不通」怎么解释

```
推杆 → 死区重映射      ⇔ arm_axis_percent()
     → 平方律 + 归一化  ⇔ arm_pose_stick_velocity()
     → 限位那一步      ⇔ 二选一 ↓
```

| 策略 | 做了什么 | 走不通时 | 对应代码 |
| --- | --- | --- | --- |
| **末端域（旧行为）** | FK(current) + v·dt → 矩形钳位 → `solve_xy`（圆环钳位 + 角度限位） | 沿半径缩到弧带上**照发**；θ1 越限才整帧不动 | `stepEndDomain()` ⇔ 旧 `arm_pose.cpp` 的 `cartesian_step`+`apply_xy` |
| **贴边滑（现行固件）** | ① 位置法：目标点沿摇杆方向，解不出就对半缩步 → ② 关节兜底 | 位置法停住后，交给关节域沿墙滑 | `stepTangent(core, …)` ⇔ `Algorithm/src/arm_limit.cpp` 的 `tangent_step()`，由 `arm_pose.cpp` 的 `cartesian_step()` 调用 |

**贴边滑内部是两段式，顺序不能反：**

1. **位置法（主路）**：目标 = 当前末端 + `v·dt`，直接逆解。圆环钳位 / θ1 越限 / 干涉 /
   出矩形任一不过，就把目标点沿摇杆方向对半缩（1/2 … 1/128），取第一个真可达且合法的点。
   这一段保证「手到哪，末端就沿那条直线走」。
2. **关节兜底（只在①全失败时）**：摇杆正对着一堵墙，位置法一步都走不了，才把速度交给
   雅可比。候选按优先级：DLS 原方向 → x 单轴 → y 单轴 → **只动 θ1 → 只动 θ2**，
   每个候选再从整步对半回退。顶到关节限位用饱和重解（`solveJointStep`），
   越出矩形剔掉法向分量（`flattenToRect`），剩下能走的分量就是切向滑。

两段都必需，各补一个对方的死角：

| 只用关节域（v1） | 只用位置法 |
| --- | --- |
| 末端竖直向下时 DLS 的最小范数解把大臂越转越平（θ1→2°），大臂先压到车体上表面 → **只能到 y=−62.9** | 正对墙推时一步都走不了 → 顶到内弧/矩形就**整帧停死，不会沿边滑** |

「饱和重解」也不能省：双自由度解里两个关节是合伙凑位移的，把顶住的那个直接夹到边界、
另一个照原值走，剩下的那个会突然承担整段位移 —— 实测顶到 θ2=−45° 后**每帧 4.2 mm，
是期望 1 mm 的 4 倍**，末端像弹射一样窜出去。

### 8.2 实测（`node sim/verify/stick_test.js`，60 帧 × 20 ms，从 Home 出发）

| 推法 | 贴边滑 | 末端域（固件现状） |
| --- | --- | --- |
| 向内 −x | 12.0 mm，S2 停在 −100%，r 锁在内半径 228.58 | 12.4 mm，标记全是 `wall` |
| 向外 +x（到伸展极限） | 10.7 mm，**方向逆转 0 次**，单帧位移 ≤ 1.00× 期望 | 11.1 mm，二阶差 0.620（每帧重新 IK，圆环钳位来回跳） |
| 向下 −y（进 β<−15.2° 死角） | 110.8 mm，**0 帧被拒** | 92.0 mm，**28 帧 `limited` 整帧不动** |
| 向下推 600 帧 | **到 y=−77.0（地面）**，x≈224 | 卡在 y=−58.6 |
| 斜推撞矩形上界 | 沿边走了 Δy=26.7 mm，一步不越界 | 每帧把目标拽到边上（钳位照发） |

结论三条：

1. 顶到内弧时两者终点接近（边界都是那个圆），差别在「怎么到」和抖不抖。
2. 抖动差 10 倍：末端域每帧重新解 IK，目标点一越界就被投影回弧带；
   贴边滑的位置法沿直线走，只在边缘处缩步。
3. **伸到地面这件事只有位置法做得到**：关节域那条路会让大臂压到车体上表面先卡住。

### 8.3 能伸到哪：地面窗口，以及「车底下」为什么够不到

放开工作区口径之后（见 §8.6），实测能到的最低位置：

| 高度 | 能夹的 x 范围（固件精确命中 + 无干涉） |
| --- | --- |
| y = 0（车体上表面高度） | 185 ~ 244 |
| y = −20 | 184 ~ 242 |
| y = −40（底盘底面高度） | 180 ~ 238 |
| y = −60 | 191 ~ 232 |
| **y = −77（地面）** | **217 ~ 223**（只有 6 mm 宽） |

看起来「能贴地」，但请注意 **x 全在 180~244**，也就是**车体前方**（底盘前端在 x = 72.5）。
车体正下方（x = 0~72、y = −40~−77）**一个点都够不到**，原因是半径：

```
本车可达域是一条弧带：r ∈ [228.58, 244.43]（右半平面）
车体下方的半径：地面处 r = 77 ~ 105，底盘底面处 r = 40 ~ 82
→ 全部落在内半径以内，不是限位卡住，是几何上够不着
```

内半径 228.58 由 θ2 = −45°（前方只有 45° 行程）决定，**改 θ2 上限也救不了右半平面**
（θ2 上限只影响左半平面：135°→126.7、180°→92.4，仍然够不到车底）。

要做到「伸到车底下」，只有三条路，都得动结构：

| 方案 | 效果 | 代价 |
| --- | --- | --- |
| 缩短小臂（把 168.43 降下来） | 内半径 ≈ |L1−L2Σ|，L2Σ≈120 时内半径 ~44，能到车底 | 最大伸展从 244 掉到 ~196 |
| 底座加升降/前后导轨 | 相对地移动整个可达域 | 多一个自由度 + 控制 |
| 升 3R（加腕 pitch 或第五节） | 模型与限位全部重做 | 工作量最大 |

> 还有一条没确认的：`128.35` 到底是「腕点之外的工具延伸」还是「肘轴到夹爪末端的总长」。
> 按后者算 L2Σ = 128.35，内半径降到 190（右）/92（左），地面窗口变成 x≈175（更靠里但仍够不到车底）。
> 两条读法的对比见 §7 第一条。

### 8.4 移植到固件（已完成）

| 仿真里的东西 | 固件里的落点 |
| --- | --- |
| 位置法（`solve_xy` + 缩步） | `Algorithm/src/arm_limit.cpp` 的 `tangent_step()` 第①段 |
| `jacobian()` 解析式 | 同文件 `jacobian()`（`arm_kinematics` 只留 2R 几何，限位算法不塞进去） |
| `solveJointStep()` 饱和重解 | 同文件 `solve_joint_step()` |
| `flattenToRect()` 法向剔除 | 同文件 `flatten_to_rect()` |
| `stepTangent()` | `arm_pose.cpp` 的 `cartesian_step()` 换成调 `arm_limit::tangent_step()`，签名不变 |
| `feasible` 回调 | **固件没有**：只靠限位 + 矩形。要加干涉判据就在 `arm_limit.cpp` 的 `feasible_at()` 里补线段采样（`sim/verify/stick_test.js` 的 `feasible()` 是现成写法） |

几何口径不同：固件末端是**腕点**（`fore_mm = 40.08`，没有 128.35 的工具延伸），所以
`L1=76 / L2=40.08`、右半平面内半径 108.12、最大伸展 116.08 —— 仿真的 228.58 / 244.43 那组
数字是「指尖 + 工具」口径，别混用。

固件侧的验收（真代码 + 真几何，6 条断言，含与 JS 的逐帧对拍）：

```bash
g++ -std=c++14 -O2 -I Algorithm/inc Algorithm/src/arm_limit.cpp Algorithm/src/arm_kinematics.cpp \
    sim/verify/stick_probe.cpp -o sim/verify/stick_probe.exe
node sim/verify/stick_port_test.js
```

每帧开销：位置法 1~7 次 `solve_xy`（多数帧只 1 次，边界才缩步）；关节兜底只在卡死时走。
和旧版「每帧固定 1 次逆解」同量级，真机仍需 DWT 实测（`debugv0.2.md` R-4）。

### 8.6 工作区（`kWorkspace`）拟合口径

`fitWorkspaceRect()` 现在**一路扫到地面**（`ground + 2`），并且要求「有一支姿态不撞底盘/地面」。
以前从 `y ≥ 1` 起扫，等于把车前方那片贴地区域整个排除掉，摇杆永远下不去。

实测拟合结果（默认几何）：`x −243 ~ 244`、`y −77 ~ 243`。
框很大是因为可达域本身是弧带，外接矩形必然空一大半；它只是「命令允许范围」，
真正逐点可达靠 §8.1 的限位与干涉判据。

老版本存在 `localStorage` 里的框（`y_min` 停在 0 附近）会在打开页面时**自动按新口径重拟合一次**；
手调过的请用「工作区」分组里的数字框改回来。

> 固件注意：`arm_config.hpp` 里 `static_assert(kWorkspace.x_min_mm > 0.0F)` 与这个框冲突
> （拟合值是 −243）。抄进固件时要么放开这条断言，要么把 x_min 收成 0（等于放弃左半平面）。

### 8.7 已知限制

- **关节状态不能四舍五入**。`stkStep` 里若把 `p1/p2` 取整到 0.01%，贴边滑每帧 0.004% 的
  增量会被抹成 0，状态钉死在同一帧、永远卡在墙边 —— 实测取整后只能到 y=−62.9，不取整到 −77.0。
  固件本来就是 float，别在仿真里造精度损失。
- **矩形当墙用 0.02 mm 容差**：`flattenToRect` 是线性化投影，会残留零点零几毫米的法向位移，
  严格按「必须进框」判会把自己的残差判死。末端一个舵机步进是 2.6 mm，这个容差是它的 1%。
- **两轴同时饱和就判卡死**：正对墙角推确实该停；顶在最大伸展（θ2=0 附近）时，垂直方向
  本来就没有自由度，也会表现为「推不动」。
- **干涉只查线段**（同 §7），固件侧还没有这套判据。
- **没做速度环 / 加速度限幅**：一步给多少就走多少，靠舵机 slew 兜底。顶到限位的瞬间如果
  听到「咔」一声，把 `slew_percent_per_second` 调小。
